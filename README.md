# discordbot
Testing out discord bot integration

## Playlist tags

Post a Spotify track link in the songs channel and the bot adds it to a playlist. Each **tag** points to one playlist; add one after the link to choose where the song goes:

```
https://open.spotify.com/track/4PTG3Z6ehGkBFwjybzWkR8 !relax
```

| Message | Result |
| --- | --- |
| `<link>` | Default playlist |
| `<link> you gotta hear this!` | Default playlist |
| `<link> !relax` | `relax`'s playlist only, **not** the default |
| `<link> +relax` | `relax`'s playlist **and** the default playlist |
| `<link> !relax !gym` | Both tags' playlists |
| `<link> !default` | Default playlist (same as no tag) |
| `<link> !typo` | Default playlist (unknown tags are ignored) |

- **`!` means only, `+` means also the default.** `+relax` is a shortcut for `!relax !default`.
- **Matching is forgiving:** tags are case-insensitive and can go anywhere in the message. They also work inside formatting, e.g. `**!relax**` or `(+relax)`.
- **No duplicates:** each playlist gets a song at most once, even when several tags point to the same playlist. A song that's already in a playlist isn't added again.
- **Every link counts:** all links in the message go to the selected playlists.
- **Links only:** tags in a message without a Spotify link do nothing.
- **Permissions:** songs are added with the poster's own Spotify account, so every tagged playlist must be collaborative, or otherwise editable by everyone who posts.

## Managing tags

Tags are managed in Discord with slash commands, and changes apply immediately:

| Command | What it does |
| --- | --- |
| `/tags` | Shows how to tag a song, then lists each playlist (linked, by name) with its tags, starting with the default playlist. Only you see the reply. |
| `/tag add tag:relax playlist:<link>` | Creates `!relax` (and `+relax`) for the playlist. If the tag already exists, nothing changes. |
| `/tag set tag:relax playlist:<link>` | Changes which playlist `!relax` adds to, creating the tag if it doesn't exist. |
| `/tag remove tag:relax` | Deletes the tag. Songs tagged with it go to the default playlist. |
| `/tag alias tag:relax new:chill lofi` | Creates `!chill` and `!lofi` for the same playlist as `!relax` (`tag:default` for the default playlist). Separate up to 10 names with spaces or commas. Tags that already exist are skipped, never moved: use `/tag set` to move one. |

- **Playlist links:** in Spotify, use **Share → Copy link to playlist**. The playlist must be collaborative so everyone's songs can be added. Spotify-made playlists (IDs starting with `37i9dQZF1`) are rejected because nobody can add to them.
- **Tag names:** letters and numbers, optionally joined by single `-` or `_` (`lo-fi`, `road_trip`). They're case-insensitive, and the `!` or `+` is optional when typing them in a command.
- **`default` is reserved:** it always means the playlist in `SPOTIFY_PLAYLIST_ID`.
- **Aliases:** several tags can point to the same playlist (e.g. `!relax` and `!relaxing`). `/tags` lists them together, and `/tag alias` adds them without the playlist link.
- **Changes are public:** `/tag` replies in the channel, so everyone sees what changed.
- **Who can use them:** anyone in the server, by default. Server admins can limit `/tag` to certain roles under **Server Settings → Integrations → (the bot) → Commands**.

**Pick names that say what's in the playlist.** Generic names like `!both`, `!all` or `!misc` are hard to remember. Names like `!play` or `!help` collide with other bots' commands, and near-duplicates like `!relax`/`!relaxx` are easy to mix up.

### Where tags are stored

Playlist IDs aren't committed to this public repo. Tags live in `/data/playlist-tags.yaml` inside the `discord-bot-data` Docker volume on the server, which survives redeploys. Back it up with:

```sh
docker cp discord-bot:/data/playlist-tags.yaml .
```

The file lists each playlist once, with all the tags that add to it:

```yaml
# ╔══════════════════════════════════════╗
# ║     AUTOGENERATED - DO NOT EDIT      ║
# ...
default_playlist:
  name: Everything
  id: <SPOTIFY_PLAYLIST_ID>
playlists:
  - name: Gym Bangers
    id: <playlist ID>
    tags:
      - gym
      - workout
```

`name` is only there to make the file readable and label playlists in `/tags` and the `/tag` replies: the bot goes by `id`. `default_playlist` only holds the default playlist's name, so it's kept even when no tag adds to it; the default playlist is still set with `SPOTIFY_PLAYLIST_ID`, and the name is ignored if the IDs don't match.

Spotify access is per user, so a missing name is looked up with the Spotify account of whoever runs `/tags`, `/tag add`, `/tag set` or `/tag alias`, and saved. Names are also refreshed at most once an hour when someone adds a song to the playlist, so renames show up. A lookup never asks anyone to connect Spotify; if it fails, the old name (or none) is kept, and replies say "Untitled playlist" or "Default playlist" instead.

Versions before `default_playlist` was added can't read a file that has it: to roll back to one of them, delete the `default_playlist` block first.

Use `/tag` rather than editing the file: the bot rewrites it on every change, erasing comments and anything edited while it runs. If you do edit it with the bot stopped, each playlist must appear once with at least one tag, and each tag under one playlist only; otherwise the bot logs the error, falls back to the secret's tags, and `/tag` is unavailable until it's fixed.

The first time the bot starts without that file, it creates it from the `SPOTIFY_PLAYLIST_TRIGGERS` secret (format `tag=playlistID[,playlistID...];tag=playlistID`). After that, the secret is ignored and can be deleted.

Earlier versions saved tags in `playlist-tags.json`. If the YAML file doesn't exist yet but the JSON file does, the bot converts it, writes the YAML file, and renames the JSON file to `playlist-tags.json.bak` (with a timestamp added if that backup already exists). To roll back to an older version of the bot, copy the backup back over `playlist-tags.json`; tag changes made since the upgrade aren't in it.

On the next upgrade, both files exist. If `playlist-tags.json` was changed more recently than `playlist-tags.yaml` (as it is after a rollback), the bot converts it again, so tag changes made while rolled back are kept: it backs up the YAML file as `playlist-tags.yaml.bak` first (keeping its playlist names), renames the JSON file to `playlist-tags.json.bak` (timestamped if that exists), and logs a warning with both paths. Otherwise the JSON file is left over from a conversion that was interrupted, so it's just renamed to `.json.bak` and the YAML file is used. If `SPOTIFY_TAGS_FILE` still points to a `.json` file, the bot uses the `.yaml` file next to it and logs a warning to update the setting.

Tags used to point to several playlists. Older files and secrets are converted automatically: each tag keeps its first playlist other than the default one, since `+tag` now covers the default. The bot logs a warning for each tag that changed, listing the playlists it dropped, which can be recovered from the backup. If the file can't be read or written, the bot logs the error, falls back to the secret's tags, and `/tag` is unavailable until it's fixed. The bot logs `Loaded playlist triggers` with the tag names at startup.

### Other settings

| Variable | Default | Description |
| --- | --- | --- |
| `SPOTIFY_TRIGGER_PREFIX` | `!` | The single symbol that marks a tag. It can't be `+`, which marks tags that also add to the default playlist, or `` ` ``, which marks code in Discord. Avoid `$` (Docker Compose treats it as a variable) and `#`/`:` (hashtags and `:emoji:` would look like tags). |
| `SPOTIFY_REPLY_UNKNOWN_TRIGGERS` | `false` | When `true`, the bot replies `Unknown playlist: !name` when someone uses a tag that isn't configured. |
| `SPOTIFY_TAGS_FILE` | `playlist-tags.yaml` | Where tags are saved, as YAML. `docker-compose.yml` sets it to `/data/playlist-tags.yaml` on the volume. A JSON file from earlier versions is looked for at the same path with a `.json` extension. |
